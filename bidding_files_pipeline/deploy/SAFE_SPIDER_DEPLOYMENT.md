# 爬虫服务安全部署流程

本流程用于替换 `bigdata-spider-v0.01.jar`，不修改爬虫程序内部逻辑。部署期间不得启动新的 Pipeline 任务。

1. 在 Pipeline Web 页面确认当前任务已经结束，并创建 `web_runs/.maintenance`；Web API 检测到该文件后拒绝创建和重试任务。
2. 查询所有已知爬虫运行；存在 `RUNNING` 或 `RETRYING` 时继续等待，不替换 JAR。
3. 若运行未在约定窗口内排空，取消本次部署并保留现场日志，不强制中断。
4. 将新 JAR 上传为临时文件，校验文件大小和 SHA-256 后备份旧 JAR，再执行同文件系统原子重命名。
5. 通过受管服务向旧 Java 进程发送 `SIGTERM`，确认退出后启动新版本；禁止直接覆盖正在使用的 JAR。
6. 等待 `GET /spider/crawl/` 和 9081 端口健康检查通过，再验证运行状态接口和数据库连接。
7. 使用一个受控测试企业验证提交、状态轮询和落库；失败时停止新版本并恢复备份 JAR。
8. 验证完成后删除 `web_runs/.maintenance`，恢复 Pipeline Web 接收任务。

爬虫当前没有服务端“停止接收请求”接口，因此排空约束由 Pipeline 入口和部署人员共同保证。其他调用方也必须在部署窗口停止提交。
